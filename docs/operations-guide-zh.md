# 地图获客 · 完整操作文档

面向业务用户的操作说明（技术参数已对用户隐藏）。

部署地址示例：`http://124.222.208.237:8080`

---

## 1. 登录与语言

1. 打开站点 → **邀请码登录**（可重复使用，约 30 天）。
2. **换语言**：页面右上角地球图标旁的下拉框，可选中/英/印尼/马来/泰/越/菲等。选中后即时切换文案；AI 背调摘要跟随界面语言。选择写入浏览器本地，下次自动记住。

---

## 2. 两种入口：普通模式 / 智能体模式

| 模式 | 怎么用 |
|------|--------|
| **普通模式** | 左侧表单：国家 → 在哪里 → 找什么 → 半径 → 开始搜索 |
| **智能体模式** | 点「智能体模式」进入独立工作区 `/agent/`（豆包式：侧栏新建任务 + 对话） |

智能体界面用 **AI Elements** 组件展示推理链（Chain of Thought）与抓取计划（Task），不再挤在地图侧栏里。

系统一律 **深度全量**（半径内网格 + 不限数量）。目标是把用户说的「在哪里 + 找什么」在目标地点内尽量找全。

### Agent 如何尽量找全

- 点名大城市（雅加达等）且未写小半径 → 默认 **都会区 40km**，并拆成多区县锚点重叠覆盖（不是只扫市中心 3km）。
- 写了明确公里数 → 尊重用户半径。
- 每个任务：深度 + 网格 + 半径内不设数量上限。

### 半径与结果量（重要）

之前测速里的「雅加达 87 家」是 **3km 半径烟测**，不是全市。

| 半径 | 大致范围 | 预期 |
|------|----------|------|
| 3–5km | 街区/商圈 | 几十～一百+ |
| 10–15km | 城区一片 | 数百 |
| 25–40km | 大半城 / 都会区 | 往往上千（耗时长） |

点半径快捷按钮：`5 / 10 / 25 / 40(都会区)`。

### AI 模型（真实服务）

- 配置：`GRSAI_API_KEY`（必填启用）、`GRSAI_API_HOST`（默认 `https://grsaiapi.com`）、`GRSAI_MODEL`（默认 **`gemini-3.1-flash-lite`**）。
- Intent 理解 / 关键词翻译 / 背调归纳 都走同一 GRSAI OpenAI 兼容接口。
- 未配置密钥时 IntentAgent **回退规则引擎**（仍可拆任务）。前端 AI 胶囊会显示状态。

## 5. 并发：宁少勿慢 + 水平扩展

### 单机公平准入（已实现）

- 每个深度任务固定 **2 个内部 worker（满速）**，不会因为又来新任务而被稀释。
- 超过本机槽位的任务 **排队等待**，而不是一起开然后互相拖慢。
- 槽位 = `min(环境上限, 内存预算, CPU/2)`。
- UI 显示 `并发 active/slots · 满速×2`（`/api/v1/system/concurrency`）。

| 机器 | 大约满速并行 |
|------|----------------|
| 2 核 / 3.6G 生产机 | **1–2 路** |
| 4 核 / 16G 测试机 | **约 2 路**（CPU 限额；内存本可更高） |
| 环境变量硬顶 | `GMS_WEB_JOB_CONCURRENCY`（默认 4，最大 64） |

> 之前「6 路同时跑」会让每路掉到 ~17 家/分；公平准入后改为 **少路满速**，排队的稍后再跑。

### 以后要几百并发怎么做

单机 Playwright 深度抓取 **不可能** 稳定跑上百路浏览器。正确做法：

1. **水平扩展 worker**：多台机器 / 多个容器都跑 `-web`（或独立 worker），共享同一任务库/队列。  
2. 每台只设 `GMS_WEB_JOB_CONCURRENCY=2~4`，靠机器数量乘起来。  
3. 入口仍是一个 Nginx/网关；任务状态进共享 SQLite/Postgres。  
4. 可选：发现阶段用更多节点，背调异步池另开。

公式粗算：`总深度并发 ≈ 机器数 × 每机满速槽位(1~2)`。  
要 200 路满速深度 ≈ 需要约 **100+ 台** 小规格节点，或更少但更大规格的浏览器池机器。

## 6. 结果与导出

任务坞点开结果 → 导出 CSV。开启背调则抓完后再跑。

结果来自 Google Maps 公开列表 + 详情页；联系方式覆盖率因品类而异（咖啡馆邮箱常偏低，电话/WhatsApp 较高）。
